Overview Architecture

GitHub (main branch)
        │
        ▼  git push triggers
GitHub Actions CI/CD  (ubuntu-latest runner)
        │
        ├─ npm ci                    # install all deps (incl. devDeps for build)
        ├─ npm run build             # Vite → dist/index.js
        ├─ npm ci --omit=dev         # strip devDeps before zipping
        ├─ zip -r deploy.zip .       # ~50–80 MB including node_modules
        │
        ▼  az webapp deploy
Azure App Service  (Linux, Node 22 LTS)
        │
        ├─ server.js                 # entry: reads PORT from process.env at runtime
        ├─ dist/index.js             # Vite-bundled Hono app
        ├─ migrations/*.sql          # auto-applied on startup via db-adapter.ts
        └─ /home/data/app.db         # SQLite — persists across restarts in /home/

Azure Blob Storage  (allowBlobPublicAccess = false)
        └─ container: <CONTAINER_NAME>
               └─ blobs are private — served via backend SAS proxy only
ℹ️
Key design decisions:
• SQLite via better-sqlite3 — no external DB server; file lives on Azure's persistent /home/ volume.
• Blob Storage is private — browsers never receive storage keys; downloads go through a server-side SAS token proxy.
• No Cloudflare Workers at runtime — the production stack is pure Node.js on App Service.

Part 1 Azure Resource Setup (one-time)

⚠️
Run these commands once per project. They create the Azure resources that GitHub Actions will deploy into. Requires Azure CLI installed and az login completed.

1.1 — Resource Group

az group create \
  --name <RESOURCE_GROUP> \
  --location <LOCATION>

1.2 — App Service Plan (Linux)

az appservice plan create \
  --name <PLAN_NAME> \
  --resource-group <RESOURCE_GROUP> \
  --is-linux \
  --sku B1      # B1 = sufficient for a demo; upgrade to P1v3 for production

1.3 — Web App (Node 22 LTS)

az webapp create \
  --name <APP_NAME> \
  --resource-group <RESOURCE_GROUP> \
  --plan <PLAN_NAME> \
  --runtime "NODE:22-lts"

1.4 — Application Settings (environment variables)

These become process.env.* inside Node.js at runtime:

az webapp config appsettings set \
  --name <APP_NAME> \
  --resource-group <RESOURCE_GROUP> \
  --settings \
    NODE_ENV="production" \
    DB_PATH="/home/data/app.db" \
    PORT="8080" \
    AZURE_STORAGE_CONNECTION_STRING="<paste-connection-string-from-Part-2>" \
    AZURE_STORAGE_CONTAINER="<CONTAINER_NAME>"
💡
Why /home/data/app.db?
Azure App Service's /home/ directory is backed by Azure Files and persists across instance restarts and redeployments. Everything outside /home/ is ephemeral — wiped on restart. Always store SQLite here.

1.5 — Startup Command

az webapp config set \
  --name <APP_NAME> \
  --resource-group <RESOURCE_GROUP> \
  --startup-file "node server.js"

1.6 — Custom Domain (optional)

az webapp config hostname add \
  --webapp-name <APP_NAME> \
  --resource-group <RESOURCE_GROUP> \
  --hostname <CUSTOM_DOMAIN>

Then add a CNAME record at your DNS provider: <subdomain> → <APP_NAME>.azurewebsites.net

Part 2 Azure Blob Storage Setup (one-time)

2.1 — Create Storage Account

az storage account create \
  --name <STORAGE_ACCOUNT> \
  --resource-group <RESOURCE_GROUP> \
  --location <LOCATION> \
  --sku Standard_LRS \
  --allow-blob-public-access false   # CRITICAL — enforces private blobs account-wide
🔒
--allow-blob-public-access false is mandatory. This disables public URLs for every blob in the account. Documents are private and served only via the backend SAS proxy. Without this flag blobs are publicly readable by anyone with the URL.

2.2 — Create the Blob Container

az storage container create \
  --name <CONTAINER_NAME> \
  --account-name <STORAGE_ACCOUNT>
⚠️
Do not pass --public-access blob. The account-level flag blocks it and throws PublicAccessNotPermitted.

2.3 — Get the Connection String

az storage account show-connection-string \
  --name <STORAGE_ACCOUNT> \
  --resource-group <RESOURCE_GROUP> \
  --query connectionString \
  --output tsv

The output looks like this — copy the entire string:

DefaultEndpointsProtocol=https;AccountName=<STORAGE_ACCOUNT>;AccountKey=XXXX==;EndpointSuffix=core.windows.net

This value goes into both the Azure App Settings (step 1.4) and the GitHub Secret (step 3).

Part 4 GitHub Actions Workflow

Create this file in your repository: .github/workflows/azure-deploy.yml

# .github/workflows/azure-deploy.yml
name: Deploy to Azure App Service

on:
  push:
    branches:
      - main

jobs:
  deploy:
    runs-on: ubuntu-latest   # MUST be Linux — better-sqlite3 native module is Linux-only

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Set up Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '22'
          cache: 'npm'

      # Install ALL deps — devDeps (vite, typescript) needed for the build step
      - name: Install all dependencies
        run: npm ci

      # Vite compiles src/ → dist/index.js
      - name: Build frontend
        run: npm run build

      # Strip devDeps before zipping — reduces zip size by ~60%
      - name: Install production dependencies only
        run: npm ci --omit=dev

      # Fail fast if anything critical is missing
      - name: Verify key files exist
        run: |
          ls -lh server.js dist/index.js
          ls -lh node_modules/@hono/node-server/dist/index.mjs
          ls -lh node_modules/better-sqlite3/prebuilds/linux-x64.node
          echo "node_modules size: $(du -sh node_modules/)"

      - name: Azure Login
        uses: azure/login@v2
        with:
          creds: ${{ secrets.AZURE_CREDENTIALS }}

      # Sync secrets → Azure App Settings so process.env picks them up
      - name: Configure App Service settings
        run: |
          az webapp config appsettings set \
            --name <APP_NAME> \
            --resource-group <RESOURCE_GROUP> \
            --settings \
              AZURE_STORAGE_CONNECTION_STRING="${{ secrets.AZURE_STORAGE_CONNECTION_STRING }}" \
              AZURE_STORAGE_CONTAINER="${{ secrets.AZURE_STORAGE_CONTAINER }}"
          echo "✅ App settings synced"

      # Zip the deployment package — exclude source, secrets, and local dev artifacts
      - name: Create deployment zip
        run: |
          zip -r deploy.zip . \
            --exclude "*.git*" \
            --exclude "*.zip" \
            --exclude ".env*" \
            --exclude "data/*" \
            --exclude ".wrangler/*" \
            --exclude "src/*" \
            --exclude "vite.config*" \
            --exclude "tsconfig*" \
            --exclude "wrangler*" \
            --exclude "ecosystem*" \
            --exclude "*.md"
          echo "Zip size: $(du -sh deploy.zip)"
          echo "Spot-check zip contents:"
          unzip -l deploy.zip | grep -E "(server\.js|dist/index\.js|node_modules/@hono|better-sqlite)" | head -6

      # Upload zip — App Service extracts and runs startup-file
      - name: Deploy zip to Azure
        run: |
          az webapp deploy \
            --name <APP_NAME> \
            --resource-group <RESOURCE_GROUP> \
            --src-path deploy.zip \
            --type zip
          echo "✅ Deployment completed"

      - name: Restart app
        run: |
          az webapp restart \
            --name <APP_NAME> \
            --resource-group <RESOURCE_GROUP>
          echo "✅ App restarted"

      # Poll every 15 s for up to 10 minutes — fail the job if app doesn't come up
      - name: Wait for app to come online
        run: |
          echo "Polling https://<APP_NAME>.azurewebsites.net ..."
          for i in $(seq 1 40); do
            CODE=$(curl -s -o /dev/null -w "%{http_code}" -L --max-time 15 \
              https://<APP_NAME>.azurewebsites.net/ 2>/dev/null || echo "000")
            echo "$(date -u '+%H:%M:%S') Attempt $i/40: HTTP $CODE"
            if [ "$CODE" = "200" ]; then
              echo "✅ App is live!"
              exit 0
            fi
            sleep 15
          done
          echo "⚠️ App did not return 200 within 10 minutes — check Kudu logs"
          exit 1

Part 5 Application Code Requirements

5.1 — server.js (entry point — NOT bundled by Vite)

// server.js — plain Node.js, deployed alongside dist/index.js
import { serve } from '@hono/node-server'
import app from './dist/index.js'

// Read PORT at true runtime — Azure injects it; never bake it into the Vite bundle
const port = Number(process.env.PORT) || 8080
console.log(`🚀 Starting on port ${port}`)

serve({ fetch: app.fetch, port })
⚠️
Critical: process.env.PORT must be read inside server.js at runtime, not inside src/. If it gets baked into dist/index.js by Vite, it will be undefined at build time and the app will bind to the wrong port.

5.2 — package.json scripts

{
  "scripts": {
    "start": "node server.js",           // Azure startup command
    "build": "vite build",               // GitHub Actions build step
    "dev":   "NODE_ENV=development DB_PATH=./data/app.db node server.js"
  },
  "engines": { "node": ">=22.0.0" }
}

5.3 — Database path pattern

// src/lib/db-adapter.ts
const dbPath = process.env.DB_PATH || './data/app.db'
// Production: DB_PATH=/home/data/app.db  (set in App Settings)
// Local dev:  falls back to ./data/app.db

5.4 — Auto-migrations on startup

The db-adapter runs all migrations automatically when the Node process starts, tracked via a schema_migrations table so each file runs exactly once:

// src/lib/db-adapter.ts
const MIGRATION_FILES = [
  './migrations/0001_initial.sql',
  './migrations/0002_seed.sql',
  // ... add new files here in order ...
  './migrations/00NN_latest_change.sql',
]
runMigrations() // called at module load — before any request is handled
✅
Adding a migration: create migrations/00NN_description.sql, append its path to MIGRATION_FILES, commit and push. The next deploy auto-applies it on startup.
⚠️
Write safe SQL: use CREATE TABLE IF NOT EXISTS and ALTER TABLE ADD COLUMN (not DROP TABLE) so existing data survives redeploys.

5.5 — Blob Storage — private with server-side SAS proxy

Because allowBlobPublicAccess=false, the browser can never access a blob URL directly. The flow is:

  1. Frontend calls GET /api/documents/serve?url=<blobUrl>&filename=<name>
  2. Backend generates a short-lived (15 min) SAS token using HMAC-SHA256 over the account key — pure Node crypto, no Azure SDK needed at request time
  3. Backend fetches the blob server-side using the SAS URL and streams the response to the browser

The SAS string-to-sign for Azure Blob service SAS version 2020-08-04 — the field order is strict and must match exactly:

#Field nameValue used
1signedPermissions"r"
2signedStartISO 8601 UTC, ~1 min in the past
3signedExpiryISO 8601 UTC, 15 min in the future
4canonicalizedResource"/blob/{accountName}/{container}/{blobName}"
5signedIdentifierempty string
6signedIPempty string
7signedProtocolempty string
8signedVersion"2020-08-04"
9signedResource (sr)"b" (blob)
10signedSnapshotTimeempty string
11rsccempty string (Cache-Control override)
12rscdempty string (Content-Disposition override)
13rsceempty string (Content-Encoding override)
14rsclempty string (Content-Language override)
15rsctempty string — NO trailing \n on this last field
 
// Node.js implementation — pure crypto, no Azure SDK at request time
const { createHmac } = await import('node:crypto')  // dynamic import avoids DOM check

const strToSign = [
  perms, start, expiry, canonicalizedResource,
  '', '', '',          // signedIdentifier, signedIP, signedProtocol
  version,               // "2020-08-04"
  signedResource,        // "b"
  '',                    // signedSnapshotTime
  '', '', '', '', ''    // rscc, rscd, rsce, rscl, rsct
].join('\n')

const sig = createHmac('sha256', Buffer.from(accountKey, 'base64'))
  .update(strToSign, 'utf8')
  .digest('base64')

🔴
Always use an absolute path under /home/ for SQLite in production. Set DB_PATH=/home/data/app.db in App Settings. The db-adapter.ts must mkdir -p the directory before opening the database.

Part 10 Common Errors & Fixes

Error messageRoot causeFix
ENOENT: no such file, open './migrations/...' CWD is not the project root at startup Ensure startup command is node server.js (not cd src && node ...) and migrations/ is included in the zip
PublicAccessNotPermitted on blob upload Passing { access: 'blob' } to createIfNotExists() Remove the access parameter entirely — the container inherits the account-level private setting
AuthenticationFailed / 403 on blob download Wrong SAS string-to-sign field order or trailing \n after last field See Part 5.5 — 15 fields in exact order, joined by \n, no trailing newline on field 15

better-sqlite3 native module error Built on macOS/Windows, deployed to Linux — native binary mismatch Always build on ubuntu-latest in GitHub Actions — never zip from a Mac or Windows machine
